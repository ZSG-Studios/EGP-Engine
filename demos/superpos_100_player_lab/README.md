# Superpos courier arena

Run `launch.ps1` (30 minutes) or `python run_lab.py --duration 1800 --local-server` from this folder. By default the headless native dedicated server runs on this PC over loopback. `launch.ps1 -RemoteServer` (or `run_lab.py` without `--local-server`) instead streams this lab's source to the canonical remote checkout and runs the server on the build PC at 10.77.64.1, using the existing SSH administrator key and WireGuard tunnel; no VPN configuration or credentials are changed. Either way the native editor binary must already exist in the engine bin directory; the lab never builds.

Four local native client processes each host 25 independent Superpos sessions and independent courier brains. A fifth local native process is your playable client, player 100, for 101 streams total. All local lab processes share the first four logical CPUs (half of this PC) and cap rendering at 60 FPS. Windows priority decides who waits inside that budget: the packet proxy, dedicated server and your window run above normal, the 100 bot brains below normal.

WASD moves relative to the camera, Shift sprints, Space jumps, F applies a server-validated physics shockwave to nearby obstacles, V swaps your male/female mannequin, right-drag orbits and the wheel zooms. Visit the four coloured depots to deliver parcels. Your avatar is white. Bots avoid nearby players and obstacles using their own delayed network observations. Bots with fresh observations can independently sprint; stale observations slow them down.

The Universal Animation Library Pro and Universal Animation Library 2 Standard are combined into 162 unique clips. Male and female mannequins share the validated 65-bone rig. Gameplay blends idle, walking, jogging, sprinting, jump start/air/landing and the UAL2 throw gesture for shockwaves. The carry walk is used at very slow speeds. The other supplied clips remain available in the shared animation library. Each visible character has its own playback state; mesh and clip resources are shared, and hidden characters pause their animation. In-place assets keep animation from moving the server-owned collider. Licences and asset hashes are in `assets/ual2`; attribution: Quaternius, CC0.

`verify_avatar.gd` checks 14 male/female poses using actual skeletal changes and validates every clip target against the female rig. It passed headless and Vulkan checks and produced `animation-receipt.json` and `animation-gallery.png` in the fixed diagnostics directory. No Blender conversion or native engine rebuild is required; the engine's native GLTFDocument loads the source GLBs at runtime.

Keys 1–5 select your own network profile: fibre, broadband, busy WiFi, mobile or poor. O creates a six-second outage on your stream. These controls alter the packet proxy, independently of the bots. The supervisor waits for your requested outage to end before retrying a failed association.

| Bot IDs | Added one-way up/down delay | Jitter | Random loss | Wire rate per direction |
| --- | --- | --- | --- | --- |
| 0–19 fibre | 5 / 7 ms | 1 ms | 0.05% | 1 MB/s |
| 20–39 broadband | 14 / 21 ms | 4 ms | 0.3% | 300 kB/s |
| 40–59 busy WiFi | 25 / 35 ms | 18 ms | 2% | 100 kB/s |
| 60–79 mobile | 75 / 95 ms | 35 ms | 4% | 45 kB/s |
| 80–99 poor | 120 / 150 ms | 65 ms | 7% | 24 kB/s |

Upload rate is 60% of the table rate. Profiles are synthetic incremental impairments on top of the actual VPN/Internet path, not promises of a particular end-to-end RTT. Per-direction seeded jitter is correlated; WiFi/mobile/poor profiles also use two-state burst loss, duplication and expedited packets that cause reordering. Queue capacity and serialization are bounded. The proxy never decrypts gameplay traffic. These impairment categories follow the [NetEm model](https://www.man7.org/linux/man-pages/man8/tc-netem.8.html); this Windows proxy is not Linux NetEm and does not claim a calibrated ISP trace.

At 20–27 seconds, WiFi/mobile bandwidth drops to one quarter. At 30–39 seconds all poor-cohort traffic is dropped. At 55 seconds all bot paths become clean for a measured recovery phase; your chosen profile remains active. Terminal associations retry independently on coordinated fresh epochs with ten-second minimum backoff. Provisioning keys are random per stream and passed through private stdin, never saved to files or printed. Epoch controls and telemetry contain no keys.

Deterministic hybrid (default). The server owns the authoritative 60 Hz native EGPBox3DWorld: 101 humanoid capsules, the playground props and native Box3D exhibits (cloth, chain and spring joints). All physics is Box3D: a native fluid volume (EGPBox3DWorld.configure_fluid) floats the exhibit blocks and swimming players, and ground contact for jumping comes from one batched Box3D ray query per tick. Every client, each of the 100 bots included, is an independent deterministic client with its own Superpos session, input history, command decoder and keyframe join. A joining client receives one keyframe (Box3D snapshot, gameplay actors and the command table, about 80-95 KB zstd) in chunks sent one at a time, then simulates the same world bit-exactly from the relayed per-tick command stream. Your avatar is predicted and reconciled against the exact world at the input tick the server consumed; other characters and props render interpolated from your local simulation. Bot processes advance one shared world per process (from one bot's stream) so their brains can see positions; every bot still decodes its own stream.

Network design (all in the Superpos core, bound by Superpos-EGP). Inputs are 6 bytes (direction, flags, facing at 1024 steps), recorded once per tick and resent until acknowledged. The server plays each client's inputs out through an adaptive jitter buffer and relays everyone's consumed inputs: each changed slot travels as a slot gap, a changed-byte mask and only the changed bytes, and each client's own processed tick rides along privately. Batches are fresh-first with one redundant tick in leftover space; a client parks up to 64 batches beyond a gap, and a stalled acknowledgement (2 x transport sRTT) rewinds the stream to it, so a loss costs about one repair. The server keeps 2048 ticks (34 s) of history, so slow joiners and outages catch up without another keyframe. Reliable delivery retries after the measured RTO, and message lifetimes start at first send. Congestion control keeps a 16 KiB/s real-time floor so random wireless loss cannot starve the stream. A client whose input history fills during an outage drops its oldest inputs, and the server's playout resynchronizes. Command bandwidth is about 13 kB/s per client at 101 players.

Measured on the 80-second local-server qualification (2026-10-09): LAB_PASS for 101 clients with one keyframe per bot (re-admitted blackout bots rejoin with a fresh one), every cohort's median command lag 0.15-0.18 s behind the server, your lockstep lag p95 5 ticks with zero prediction error, your frame p50/p95 16.6/20 ms (60 fps; animation LOD phases are spread so reduced-rate characters never update in one frame), and the server's tick interval p95 16.7 ms at 59.6 Hz with application p95 10 ms. Telemetry computes percentiles only every 30 s and at the end, so it never costs a frame; mass re-admission after the blackout still briefly stalls server and proxy (DTLS handshakes), the next server-side item.

This uses native UDP/DTLS sessions, canonical publication, receipts, fresh-epoch rejection and native physics. Client extrapolation is application code, not a registered Superpos native replay provider. The server uses pre-provisioned connected UDP associations, not public matchmaking, a multi-peer listener or a NAT traversal service. SSH carries bootstrap/supervision and diagnostic telemetry; gameplay crosses the actual UDP/VPN path. Bots never read global server diagnostic positions.

Fixed evidence: `EGP-Engine/.build/diagnostics/superpos-100`. `receipt.json` records the latest completed run; `qualification.json` preserves the compact 80-second qualification summary, including per-stream readiness, blackout recovery and actual packet-fault counts. Solver-step p95 excludes networking/application frame cost and does not establish a 101-player production capacity limit. Physical human key presses were not automated.

The launcher and native processes have finite duration watchdogs. The remote firewall rule `EGP-Superpos-100-Lab` permits only VPN source 10.77.64.2 to UDP ports 48000–48100 at 10.77.64.1. Keep one WireGuard tunnel active. A short two-bot remote probe is available with `--bots 2 --no-human --duration 15`; full fault/recovery qualification needs at least 65 seconds.
